Introduction

As one of Europe’s largest and most diverse cities, London exhibits significant and concerning crime issues. Understanding how crime is distributed across space and time is essential for not only informing evidence-based policy and analysis to address the problem but also for improving residents’ sense of security and will-being.

Therefore, this project examines crime patterns in London, particularly in 2024, incorporating police station locations to provide additional contextual understanding. Part I-A Automated Data Collection

To explore crime, this project collects two datasets: street-level crime records from the UK Police API and police station location data from OpenStreetMap (OSM). API technique is selected to do the automated data collection. Output sections for the two collected datasets show the variables contained in the datasets and the corresponding values of the first six observations, to illustrate stuctures of the datasets.

Firstly, since the crime data contains longitude and latitude, a spatial bounding box based on approximate London coordinates was defined to collect crime data for the London area. This supports API querying, as the UK Police Street-level Crime API requires a polygon (poly) parameter defined by longitude and latitude. A grid-based polygon approach was used to keep polygons small, reducing the risk of exceeding API limits, although this increases request time.

#Create London polygon for data collection with longitude and latitude


lat_min <- 51.38
lat_max <- 51.67
lng_min <- -0.56
lng_max <- 0.28

make_grid_polys <- function(lat_min, lat_max, lng_min, lng_max, step = 0.05) {
  
  lats <- seq(lat_min, lat_max, by = step)
  lngs <- seq(lng_min, lng_max, by = step)
  
  polys <- list()
  
  for (i in seq_len(length(lats) - 1)) {
    for (j in seq_len(length(lngs) - 1)) {
      
      poly <- paste(
        paste(lats[i],   lngs[j],   sep = ","),
        paste(lats[i],   lngs[j+1], sep = ","),
        paste(lats[i+1], lngs[j+1], sep = ","),
        paste(lats[i+1], lngs[j],   sep = ","),
        sep = ":"
      )
      
      polys <- append(polys, poly)
    }
  }
  
  polys
}

london_polys <- make_grid_polys(
  lat_min = 51.38,
  lat_max = 51.67,
  lng_min = -0.56,
  lng_max = 0.28,
  step = 0.07
)

To request data with the UK Police API, a safe_get_json function is implemented to handle potential failures, errors, or empty responses when retrieving large volumes of data. Instead of interrupting execution, the function allows the collection process to continue, ensuring a smoother multi-month, multi-polygon data collection process.

A second function, get_crime_poly, ensures API compliance by requiring both polygon and date parameters. After defining the date (all months from 2020-2024), the data is collected iteratively by looping over all London grid polygons and monthly dates. The messages help monitor the collection process and identify problematic polygon or date if errors occur. Lastly, the poly and date variables are appended to each record to facilitate subsequent analysis.

Finally, the crime dataset is constructed by binding the results across all polygon–month combinations.

#Use a function to safely request JSON data from the API, and avoid crashing when errors or empty responses return
safe_get_json <- function(url) {
  res <- GET(url)
  status <- status_code(res)
  txt <- content(res, "text", encoding = "UTF-8")
  
  if (status != 200) {
    message("Status ", status, " for URL: ", url)
    return(data.frame())
  }
  
  if (grepl("^\\s*<", txt)) {
    message("HTML returned for URL: ", url)
    return(data.frame())
  }
  
  if (nchar(txt) < 2) {
    message("Empty response for URL: ", url)
    return(data.frame())
  }
  
  tryCatch(
    fromJSON(txt),
    error = function(e) {
      message("JSON parse error for URL: ", url)
      return(data.frame())
    }
  )
}

#Build the API request for a given polygon and month, then use the previous function to collect crime data
get_crime_poly <- function(poly, date) {
  url <- paste0(
    "https://data.police.uk/api/crimes-street/all-crime?",
    "poly=", URLencode(poly),
    "&date=", date
  )
  safe_get_json(url)
}

all_results <- list()
counter <- 1

for (p in london_polys) {
  for (d in dates) {
    
    message("Fetching poly ", counter, "/", length(london_polys), " for date ", d)
    
    df <- get_crime_poly(p, d)
    
    if (nrow(df) > 0) {
      df$poly_id <- counter
      df$date <- d
      all_results[[length(all_results) + 1]] <- df
    }
    
    Sys.sleep(0.5)
  }
  
  counter <- counter + 1
}

This function generates street rank data for Shiny app. It filters crime category and counts of crime on each street, it then rank the street according to number of a particular crime category in 2024. This allows identification of local crime hotspots and facilitates comparative analysis across different types of crime.

get_street_ranking <- function(crime_type,
                               month = "all",
                               top_n = 10) {
  
  df <- ranking_data
  
  df <- df %>% filter(category == crime_type)
  
  df %>%
    count(street_clean, sort = TRUE) %>%
    slice_head(n = top_n)
}

Overall, these datasets have substantial social science significance. Visualisations produced using these datasets enable spatial analysis of crime, spatial inequality and so on. The inclusion of police station locations further supports examination of policing resources, accessibility, and their relationship to crime patterns. Together, the datasets provide a rich empirical foundation for policy-making aimed at improving socio-economic outcomes. Additionally, individuals can use the maps and plots to avoid higher-risk areas and improve personal safety.

However, these datasets have limitations. In the data collection process, despite dividing London into many small polygons, the Police API will return a 503 error if a custom area contains over 10,000 crimes, which leads to missing records in some polygons, such as around Brixton. Similarly, the police station data from OSM are incomplete. These non-random missingness may affect the accuracy and significance of subsequent analyses and visualisations.

Part II-A Building an Interactive Dashboard with R Shiny

Using the organised datasets, an interactive Shiny dashboard is produced. It contains three complementary analytical sections, each designed to show different dimensions of crime patterns in London in 2024. Although the dataset covers records from 2020 to 2024, given the large amount of information about crime and my intention to be more focused, this Shiny app only explore 2024 crime patterns.

The crime map visualises the spatial distribution of crime by category using map_data with clustered point markers due to the large amount of points. This enables users to identify spatial hotspots and observe how crime clusters vary across places. The optional overlay of police station locations provides additional spatial contexts which enables users to compare crime pattern and policing infrastructure. Based on the map, Central London and East London exhibit higher crime counts than other parts. While it is also worth noting that the highest concentration of police stations is also located in Central London.

The top streets section identifies areas or streets with the highest crime counts using ranking_data. Bar charts are used to rank as they enable clear comparisons. The results reveal that parking areas record the highest number of crime incidents, followed by supermarkets and shopping areas. An interactive pie chart further illustates crime categories within a selected high-crime area. Across the top ten areas, violent-crime consistently represents the largest proprotion (>34% for all), followed by anti-social behaviour.

The last section, the temporal patterns section, explores how crime varies over time using trend_data. Line charts are used to display monthly trends for specific crime categories. It shows that there are seasonal variations for all crime types. The monthly bar chart enables cross-category comparison, illustating how the distribution of crime types varies over time.

Overall, the dashboard integrates spatial, categorical, and temporal perspectives, using interactive visualisations to improve understanding of crime patterns in London and urban crime data.
